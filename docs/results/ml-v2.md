# ML v2 실행 결과 및 시나리오 행동 패널 검증 보고서

작성일: 2026-08-05  
평가 기준일: 2025-12-30  
실행 대상: `snapshot49 + scenario_action + lgb_regressor`

## 1. 요약

최신 중복 시나리오 해소 구현을 적용해 ML 파이프라인을 처음부터 다시 실행했다. 원천 행을 날짜·종목 단위로 임의 병합하지 않고, `날짜 × 종목 × 시나리오`를 하나의 행동 후보로 보존했다. 같은 행동 키가 완전히 동일한 경우만 축약하고, 실행값·피처·타깃이 충돌하는 중복은 학습에서 제외했다.

2026년 데이터는 수집이 완료되지 않았으므로 모든 주 평가에서 제외했다. 2017–2025 OOF에서 모델의 선별력은 유지됐지만, 시나리오 중복을 보수적으로 제외한 실제 종목 패널에서는 표본이 줄고 최대 낙폭이 40%를 넘었다. 따라서 연구용 후보로는 유효하나 실전 승격 결과로 보아서는 안 된다.

핵심 결과는 다음과 같다.

- Top-1 평균 순수익: **+1.457%**
- Top-3 평균 순수익: **+0.902%**
- Sharpe: **5.67**
- 최대 낙폭: **40.72%**
- 승률: **61.72%**
- Profit Factor: **2.57**
- 날짜·종목 중복 제거 후 Top-1 정책 수익: **+1.449%**

## 2. 실행 범위와 재현 조건

| 항목 | 설정/결과 |
|---|---:|
| 원천 파일 | `data/parquet/trade_log.parquet` |
| 원천 행 수 | 33,934 |
| 학습 피처셋 | `snapshot49` + 시나리오 one-hot/context |
| 최종 피처 수 | 60 |
| 모델 | LightGBM Huber Regressor |
| CV | Purged Group Time-Series Walk-Forward |

| Purge gap | 1 거래일 |
| 그룹 키 | `trade_date` |

| 왕복 비용 | 타깃 생성 시 0.20% 1회 차감 |
| 패널 모드 | `scenario_action` |
| 평가 종료 | 2025-12-30 |
| 외부 데이터 | 사용하지 않음 |
| 캡처 시각 | 원천에 없어 검증하지 않음 |

실행 시 `build_ml_dataset(..., feature_set="snapshot49", panel_mode="scenario_action")`으로 정제·피처 생성 후, 수치 피처만 `run_model_pipeline`에 전달했다. 기존 모델 아티팩트는 덮어쓰지 않았다.

## 3. 데이터 및 중복 처리

### 3.1 행 수 변화

| 단계 | 행 수 |
|---|---:|
| 원천 로그 | 33,934 |
| 시나리오 행동 패널 생성 후 | 33,792 |
| 충돌 중복 reject | 114 |
| 2025년 말 이전 평가 입력 | 33,678 |
| OOF 예측 | 31,045 |

시나리오 행동 패널은 다음 규칙을 적용했다.

1. 서로 다른 `chart_analysis`는 같은 날짜·종목이어도 별도 행동으로 유지한다.
2. 동일한 `(trade_date, stock_code, chart_analysis)` 키의 행이 완전히 같으면 한 행으로 축약한다.
3. 동일 키에서 실행 가격, 피처 또는 타깃이 다르면 어느 행도 대표값으로 선택하지 않고 `conflicting_duplicate_action` reject로 이동한다.
4. 시나리오별 one-hot(`scenario_is_sangtta` 등)와 날짜·종목 컨텍스트(`scenario_count_for_stock_date`, `has_sangtta_for_stock_date`, `is_multi_scenario_stock_date`)를 추가한다.

이 방식은 `상따`를 무조건 우선하지 않는다. 상따는 하나의 행동 후보이며, 최종 포트폴리오 단계에서만 정책에 따라 선택·제외한다.

## 5. 기존 결과와의 비교

직전 내부 재학습 결과(`snapshot49 + lgb_regressor`, raw rows)와 비교하면 다음과 같다.

| 지표 | 기존 raw rows | 최신 scenario_action | 변화 |
|---|---:|---:|---:|
| Top-1 | +1.545% | +1.457% | -0.088%p |
| Top-3 | +0.926% | +0.902% | -0.024%p |
| Sharpe | 5.88 | 5.67 | -0.21 |

중복을 정리한 뒤에도 Top-1 성과와 Sharpe는 크게 무너지지 않았다. 반면 MDD가 증가했으므로, 중복 제거가 성과를 과장하던 문제는 줄였지만 위험이 낮아졌다고 말할 수는 없다.

## 6. 날짜·종목 유일 정책 결과

`resolve_stock_actions(mode="exclude_multi_scenario")`로 날짜·종목당 행동이 하나인 그룹만 남긴 뒤 `simulate_top_k_policy(top_k=1)`를 실행했다.

| 항목 | 결과 |
|---|---:|
| 해소 후 행 | 30,739 |
| 제외된 OOF 행동 | 306 |
| 날짜·종목 중복 | 0건 |
| Top-1 평균 순수익 | +1.449% |
| 승률 | 61.72% |
| Profit Factor | 2.55 |
| Sharpe | 5.63 |
| 최대 낙폭 | 40.72% |

정책 수익이 전체 행동 후보 패널의 +1.457%와 거의 같은 것은 제외된 행이 상대적으로 적기 때문이다. 그러나 이 결과는 다중 시나리오 종목을 포트폴리오에서 제거하는 보수적 평가이며, `상따`와 다른 시나리오 중 어느 행동을 실제로 실행할지 결정한 결과가 아니다.

`score_best_action`은 예측 점수가 가장 높은 행동을 선택하는 연구용 민감도 분석 모드이고, 실현 타깃으로 선택하지 않는다. `require_final_action`은 실제 운영 입력에 최종 실행 행동이 정확히 하나로 확정된 경우에만 허용한다.

## 7. 해석과 한계

- 이 결과는 5-fold OOF 연구 결과이며 완전히 사용하지 않은 독립 holdout 성과가 아니다.
- 원천 데이터에는 실제 캡처 시각이 없다. 따라서 point-in-time 누수 부재를 증명한 결과가 아니다.
- `target_return`은 이미 왕복 비용 0.20%가 차감된 decimal net이다. 백테스트에서 비용을 다시 차감하지 않았다.
- Top-1 turnover 100%는 매일 보유 종목이 바뀌는 이상적 선택 지표다. 실제 체결·유동성·슬리피지를 반영하면 성과가 낮아질 수 있다.
- 최대 낙폭 40.72%는 단순 누적 일별 수익 기준이며, 레버리지·현금 비중·손실 제한을 적용한 운용 MDD가 아니다.
- 2026년 결과는 데이터 미완성으로 모델 선택과 점수 산정에 사용하지 않았다.

## 8. 최종 판단

최신 `scenario_action` 구현은 기존의 임의 `drop_duplicates`보다 데이터 의미를 보존한다. 모델 성능은 기존 결과 대비 소폭 하락했지만, 중복 시나리오를 명시적으로 처리한 뒤에도 2025년까지 양의 선별력이 남았다.

현재 단계의 결론은 다음과 같다.

1. 연구용 기본 모델: `snapshot49 + lgb_regressor`
2. 시나리오 패널: 서로 다른 시나리오는 보존하고, 충돌 동일 키는 reject
3. 역사 평가 기본 정책: `exclude_multi_scenario`
4. 실전 승격: 보류
5. 다음 검증: 최종 실행 행동이 저장된 신규 데이터로 `require_final_action`을 적용한 독립 OOS와 paper-trading

현재 모델을 100점 기준으로 환산하면 연구용 완성도는 약 **60점대**다. 선별력은 충분하지만, 실제 캡처 시각·독립 OOS·체결 비용·40%대 MDD 문제가 남아 실전 운용 점수로는 평가할 수 없다.

## 2. Core Architecture Decisions

### ADR-001: Parquet 컬럼형 스토리지 및 원자적 파일 교체

* **Decision**: 전통적인 RDBMS나 SQLite 대신 Apache Parquet 기반 컬럼형 파일 포맷과 OS 수준의 원자적 파일 교체(`atomic_write_parquet`)를 채택한다.
* **Why**: 10년 치 전종목(2,500+) 일별 시세 패널에서 15:20 의사결정 시점에 28차원 피처를 1.0초 이내로 슬라이싱해야 한다. Apache Arrow 기반 제로카피(Zero-Copy) 메모리 매핑은 RDBMS의 행 단위 직렬화 오버헤드를 완전히 제거하며, 로컬 파일시스템 기반으로 인프라 운영 복잡도를 극소화한다.
* **Trade-off**: Parquet은 컬럼 단위 불변 압축 포맷이므로 개별 행의 실시간 인플레이스 업데이트가 불가능하다. 이를 해결하기 위해 임시 파일(`.tmp`)에 전체 직렬화를 완료한 후 커널 `rename` 시스템 콜을 통해 원자적(Atomic)으로 갱신하는 방식을 채택했다.

### ADR-002: 4대 증권사 OpenAPI 특화 분산 라우팅

* **Decision**: 한국투자증권(KIS) 단일 벤더 의존을 탈피하고, 키움증권, KIS, LS증권, 토스증권을 각사의 기술적 강점에 맞춰 분산 라우팅한다.
* **Why**: 15:20~15:30의 10분 결정창 동안 전시장 스캔, 10단계 호가잔량 캡처, 장중 잠정수급 수집, 당일 1분봉 아카이빙을 단일 증권사(초당 요청 한도 TPS 18건)로 처리할 경우 심각한 Rate Limit 차단 및 지연이 발생한다.
  - **키움증권 (`ka10027`)**: 1회 호출당 전시장 등락률 상위 200종목을 **`0.2초`**에 반환하여 후보군 고속 스캔 전담.
  - **KIS**: 10단계 호가잔량 및 예상체결가, 장중 잠정수급 동시 조회 가능 $\to$ 15:20 의사결정 단면 정밀 수집 전담.
  - **LS증권 (`t8412`)**: 1회 호출로 390개 1분봉 전체 일괄 조회 $\to$ 야간 분봉 아카이빙 전담 (API 호출 수 **`390배`** 절감).
  - **토스증권 (`/api/v1/prices`)**: 200종목 멀티 쿼트 지원 $\to$ KIS 장애 시 시세 조회 자동 폴백.
* **Trade-off**: 브로커사마다 상이한 인증 규약(OAuth2 토큰 갱신, 세션 키 관리)과 비정규화된 응답 포맷을 통합하는 추상화 게이트웨이 유지보수 비용이 발생한다.

### ADR-003: 15:20 Point-in-Time 의사결정 및 익일 09:00 기계적 청산

* **Decision**: 의사결정 시점을 15:20:00으로 강제하고 미래 데이터를 전면 배제하며, 익일 09:00 시초가에 기계적으로 전량 청산한다.
* **Why**: 15:30 확정 종가나 익일 시초가 갭을 미리 알고 매수하는 사후 정보 편향(Look-Ahead Bias)과 사후 갭 필터링은 실전 백테스트를 붕괴시키는 가장 큰 요인이다. 15:20 시점에 관측 가능한 데이터만으로 추론을 완결하고, 익일 09:00 시초가에 기계적 전량 청산함으로써 장중 리스크 노출 시간을 **`0분`**으로 제한하여 샤프 지수(Sharpe)를 극대화했다.
* **Trade-off**: 익일 장중 추가 상승(장대양봉) 기회비용을 포기해야 하지만, 장중 손실 리스크와 감정적 매매 요소를 배제하고 통계적으로 우월한 오버나잇 갭 알파에만 집중한다.

### ADR-004: 12.0bp 호가단위 틱비용 상한 필터 (`COST_AWARE_UNIVERSE`)

* **Decision**: 주가 구간별 1틱 비용이 12.0bp를 초과하는 종목 및 상한가 근접 종목(`chg_ratio >= 0.29`)을 유니버스 스크리닝 단계에서 원천 차단한다.
* **Why**: 5,000원 미만 저가주는 1호가 간격이 20~50bp에 달해, 왕복 2틱(40~100bp) 스프레드 크로싱 비용과 법정거래세(18~23bp)를 차감하면 머신러닝 예측 알파가 전액 잠식된다. 실증 분석 결과 12.0bp 캡 적용 시 기존 대비 연환산 Sharpe **`+0.84`** 향상 및 최대 낙폭(MDD) 대폭 감소가 증명되었다.
* **Trade-off**: 변동성이 극대화된 저가 테마주 일부가 사전 탈락하지만, 실전 체결 가능성과 포트폴리오의 계좌 생존율을 100% 확보한다.

### ADR-005: Combinatorial Purged CV(8,2) 및 5-Seed LightGBM 앙상블

* **Decision**: 일반 K-Fold 대신 Combinatorial Purged CV(8개 블록 중 2개 테스트 조합, 28개 무누출 경로)와 5개 시드의 LightGBM 앙상블 모델을 채택한다.
* **Why**: 금융 시계열의 강한 자기상관성(Autocorrelation)으로 인한 과적합을 차단하고, 훈련-검증 구간 사이에 **`168시간 시계열 엠바고(정보 누출 방지 유예)`** 및 퍼징(Purging)을 적용하여 정보 누출을 방지한다. 또한 단면 평균을 차감한 `date_demeaned` 타깃 학습을 통해 당일 후보군 내 상대적 랭킹 우위를 극대화했다.
* **Trade-off**: 5개 시드 앙상블 모델 운용으로 단일 추론 시간이 0.2초에서 1.1초로 증가하지만, 10분의 운영 허용 시간 창 대비 **`0.18%`** 수준에 불과하여 실시간성에 영향을 주지 않는다.

### ADR-006: 모의 원장 호스트 세션 락과 Append-only 무결성 가드 (`PaperLedger`)

* **Decision**: 가상 체결 원장에 커널 파일 잠금(`flock`) 기반 호스트 전역 세션 락과 불변(Append-only) 체결 이벤트 로깅을 도입한다.
* **Why**: 복수의 프로세스(스케줄러 catch-up, 수동 재실행 등)가 동시 실행될 때 발생하는 Read-Modify-Write 경쟁 상태(Race Condition)와 수기 수정으로 인한 감사 흔적 유실을 구조적으로 차단해야 한다. 또한 주문 수량 산정 시 15:30 확정가가 아닌 15:20 결정시점 가격을 기반으로 사이징하여 실전 MOC(Market-On-Close) 절차와 100% 일치시켰다.
* **Trade-off**: 원장 정정 시 과거 기록 덮어쓰기가 불가능하며, 반드시 명시적 보정 이벤트(`src.tools.paper_ledger_correct`)를 추가 발행해야 한다.

### ADR-007: 파일 잠금(`flock`) 기반 tar.zst 세그먼트 백업 및 보존 상한 가드

* **Decision**: 파일 단위 클라우드 동기화 대신 거래일 단위 append-only `tar.zst` 세그먼트 봉인 및 공용 락(`quant-gdrive.lock`) 직렬화 백업을 도입한다.
* **Why**: 인트라데이 틱/분봉 데이터는 일일 4만 개 이상의 소파일을 생성하므로, Google Drive API의 초당 2~3 객체 생성 한도와 충돌하여 백업이 수시간 지연되었다. 이를 단일 압축 세그먼트로 봉인함으로써 백업 소요시간을 수분대로 단축하고, 손상된 패널이 백업본을 덮어쓰지 않도록 무결성 검증 및 일일 삭제 상한(Prune Cap)을 강제했다.
* **Trade-off**: 개별 파일 단위 복원이 번거로워지며 세그먼트 단위 해제 절차가 필요하지만, 백업 소요 시간과 클라우드 API 쿼터 안정성을 압도적으로 개선했다.
